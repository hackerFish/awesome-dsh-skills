# 安全重构

## 前置

1. 立基线：跑一遍现有测试确认全绿；没有测试的模块先补关键路径测试
2. 记录意图：重构目标是"行为不变"，任何行为变化都算新需求，另开任务

## 执行纪律

- 小步原子提交：每次只做一种变换（重命名 / 提取函数 / 调整顺序），每步跑测试
- 先机械化、后设计：先用工具级重构（重命名、提取），再改设计
- 大规模改动前先 `grep` 引用面，确认影响范围
- 不顺手修 bug、不改格式：混在一起就无法回滚

## 收尾自查

- 对照重构目标逐条勾掉
- `git diff` 通读：有无意外行为变化
- 关键行为手工验证一次，不只看测试
